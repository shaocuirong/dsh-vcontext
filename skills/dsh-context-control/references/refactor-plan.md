# 控制层维护路线

此文件替代已完成的分阶段实施计划。当前功能范围见 [实现范围](progress.md)。

1. 核对目标仓库、分支、HEAD、未提交变化与调用方。使用现有公开会话和写接口。
2. 根据变更选择权威模块：来源和版本、目录、提交协调、恢复准入或阶段摘要。不要在 UI 或另一目录中复制运行时权威状态。
3. 明确数据作用域、版本读集、失效条件、预算和确认边界；缺少信号时保留 unknown。
4. 写操作遵循既有维护边界、数据库事务、宿主日志和对账协议；取消或丢确认后不盲目重跑。
5. 原文、固定引用和摘要分别表示；源正文、历史身份和恢复入口保持可用。摘要评审不替代测试证明。
6. 执行与改动匹配的专项回归，再运行必要完整回归及当前发行检查。UI 修改要检查实际截图。
7. 发布按用户当前授权及仓库版本约定执行，同步版本元数据与当前文档，保持数据库和本机配置。

专项入口和命令见 [验证说明](validation.md)。历史提交节点可由仓库 Git 标签追溯，本 skill 不再维护另一份发布流水账。
