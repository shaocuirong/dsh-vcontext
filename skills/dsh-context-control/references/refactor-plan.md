# 方案三：上下文控制层重构与进一步优化

日期：2026-10-29。交付状态：方案与 skill 已封装，运行时已完成 C0/C1 首批兼容迁移及手动压缩写入口接入。逐节点状态见[进度](progress.md)，不能将首批基础当作完整方案三。

## 1. 目标和实现基线

主线是“任务约束下的混合表示控制”：原文完整保存，当前请求按任务选择原文、稳定引用、阶段摘要或目录项。统一目录与一个协调器负责选择；执行器保留正确宿主边界和 SQLite 事务。

设计基线为 v0.17.0 / 2dcb2b7；实施分支 codex/context-control 已合并连接层 4afb083。开工时重新核对分支和实际 diff，不把该 SHA 设为永远的最低版本，验证等价接口与行为。

本方案保留已经确认的分层、权限与版本语义，详见 [contract](contract.md)。调度顺序、预算和提交语义见 [scheduling](scheduling.md)，本文只记录实施路线及节点验收。

## 3. 设计中必须显式保留的缺口

- withWrite 明确包装 compact，未统一历史维护、结果步骤写和 flush。先接手动 replacement；精细路径继续使用自身执行器，待独立动作能力可用再迁移。
- 当前 gate 只覆盖同一个 Access 的调用者；旧路径与宿主自身的并发仍需真实边界和源版本校验。
- 导航 tools/paths 已存在，但不提供完整写集或持续失效账本。
- 现有 processed_seq 是宿主元数据消费游标，不是所有上下文索引的内容版本。
- 现有三层 evidence note 不等于自动阶段摘要控制，更不等于 RAPTOR。
- 插件目前没有经过验证的通用“输入超限阻断”能力。查明宿主准入 seam 后再承诺拦截。
- compact 的 grant 不构成宿主幂等，不能自动重试丢响应操作。
- 原文可恢复不保证模型会主动查证，恢复采用率需要真实任务评估。

## 4. 节点与验收

每个节点形成独立可审查变更及验证记录。提交可以按仓库工作流进行；不把一次节点提交等同正式发版。阶段推进按实际验收，不按文档勾选强行通过。

### C0：协议与基线

修改：新增 control/protocol、只读 snapshot DTO；确认 action、reason、stop_state、版本和保护结构。一份机器可读语义定义供 Node/Python 使用或生成映射，不维护三份独立词表。

前置：核对连接层等价 withRead/withLiveCut/withWrite 契约、当前 SDK 和可用边界。

工作：
- 将旧 l1/l2 命名保留为兼容输出，内部用预算维度与动作域表达。
- 区分已存在 API、提议接口和能力不可用。
- 预览 DTO 不写访问、驻留或配额。
- 固定请求 trace、存储状态和错误结构作为兼容基线，排除时间戳等非语义字段。

验收：新增纯协议测试和必要的预览无写入用例；相同输入的旧行为可复核，缺测量不返回零。

退出条件：预算与动作来源仍不明确时不进入候选迁移。

### C1：统一候选投影，保持现有策略

修改：planner、segmentation/open-result 适配、Python 事务守卫协议。

工作：
- 一次识别来源、工具配对、动作权限、版本和保护，推荐与提交共享语义。
- 封口整页与开放 turn 的结果正文保持两种粒度。
- Python 执行时重验本地事实；旧计划过期明确返回，不无条件执行。
- 初期保留阈值、recent、resident、冷恢复和批次界限，不同时引入新策略。

验收：相同快照下推荐可应用；延迟/交错工具组不破坏；保护变化后提交拒绝；manual 结果计划优先级保持。预览和真实请求回归都要覆盖。

回退：功能开关仍路由旧策略；不得双路同时 append。

### C2：版本描述符、变更账本与失效

修改：effects、源描述符、Python 最小账本/消费游标及任务依赖查询。

工作：
- 已知工具按契约提取最小路径；任意命令与未知工具公开 unknown coverage。
- 调用时 pending，结果时 observed/unknown；失败也处理部分写入。
- 事件重放幂等，继承与 Surface 替换不成为新执行。
- 维护 source → representation/entry 的反向依赖；先撤销旧适用性再重算。
- 在当前路径读入口加入按需指纹重验；不每轮全仓哈希。
- Git、worktree、宿主历史、插件 ledger 与外部快照采用统一描述符，不强行同一版本号。

验收：同 HEAD/dirty/path 的连续编辑可区分；外部编辑、删除/重命名、失败写入、观察落后、路径数量溢出和重启重放均不错误标 fresh。固定旧 ref 仍可读。

回退：保留账本与旧版本，只禁用新派生投影；不能删除未消费的失效信号或覆盖数据库。

### C3：统一目录与当前投影、接续 delta

修改：catalog、evidence 适配、1b/1c 装配、目录分层投影。

工作：
- page/resource 共用 schema；结果是页成员，note 是派生表示。
- 稳定逻辑身份与重新分段映射明确，不把变了的来源装进旧 ID。
- 完整后端目录与请求视图区分；字节和项数预算独立。
- 文件→模块→仓库折叠保留恢复入口；现有 bounded scan 不能冒称全目录覆盖。
- 按会话保存上次成功交付基线，生成 base→target 的有界 delta。
- 来源只读、模型提议、程序更新分别约束；导航与摘要仍是非权威内容。

验收：目录不膨胀到挤掉任务状态；低层条目折叠后可恢复；缺基线/来源链不全时明确降级；未提交改动有正确引用；历史矛盾不被合并消失。

### C4：统一协调器与提交恢复

修改：coordinator、executors、receipts；逐个替换旧控制器的触发入口。

迁移顺序：
1. 手动 replacement 接入共享 withWrite，保留宿主策略和返回结构。
2. automation idle 触发/回执进入协调器，history-archive 保留维护与持久化。
3. result-projection 保留 admitted pre-step，交给同一协调状态仲裁。
4. 插件准入/驱逐沿用 SQLite 事务，统一报告动作结果。
5. 移除重复订阅、计时器和候选代码；确认没有双执行才删除旧路由。

工作：
- 合并需求、不排旧计划；同会话互斥，跨会话有界轮转。
- 实施 planned/prepared/intent/confirmed/uncertain 与对账。
- 写前重验必要 read-set，写后重测；宿主与 SQLite 不宣称跨域原子。
- host_compact 不充当精细换页兜底；无法确定是否执行时暂停重跑。

验收：BUSY/取消/依赖服务替换、同会话手动与自动冲突、append 后 flush 丢响应、回执失败及重启对账；结果步骤没有嵌套维护；自动不激活冷会话。

回退：停止新触发，排空或对账未决操作，再切旧路由；不直接切回后继续盲写。

### C5：有界恢复与请求准入

修改：resolver、read/restore/admit 路由、预算反馈和可用的请求装配 seam。

工作：
- 已知引用缓存 miss 查权威目录；未知引用才搜索。
- 缓存作用域包含 worktree/后端身份，按必要依赖失效。
- read 只返回证据；restore/admit 单独改变驻留并检查加入后容量。
- 来源展开受预算约束，返回 incomplete；保留完整序列化响应的字节/码点约束。
- 保护内容超过上限返回 protected_capacity 和缺口；检查宿主 seam 是否真能阻断请求。

验收：跨会话、同 commit 不同工作树、后端更换、不可变 ref 和可变路径；超限读取不会重新注满；缺能力时不假报拦截成功。

### C6：阶段摘要，完成方案三

C6a 先消费模型经明确操作提供的摘要候选；C6b 再考虑独立后台生成器。需要单独验证模型能力、调用预算、取消与来源权限，不能拿 compact 冒充自定义摘要服务。

工作：
- 完成子目标触发，生成带精确来源、状态、决定、约束、未解决项和错误引用的草稿。
- 来源完整性由程序检查，语义遗漏由模型/人工评审；评审与测试状态分开。
- 同阶段/来源版本最多一个任务；生成期间不持精细写租约。
- 提交前重验任务与资源，过期草稿留存但不自动激活。
- 只写局部 delta；现有摘要稳定，不每次重写全历史。
- 活动阶段的最小摘要进入 1c，其他摘要仍可调度，原文全部可恢复。

验收：精确标识符/错误回忆、跨阶段重访、矛盾来源、迟到生成和任务切换。比较相同导航指导下的完整保留、引用换页、摘要、混合表示；不同方案使用相同模型和任务预算。

摘要率、原文字节完整、恢复准确、任务成功和总调用成本分别记录，不以压缩比代替质量。

### C7：测量驱动的进一步优化

优化顺序：
1. 精确失效：按受影响资源/依赖刷新，减少全量失效。
2. 目录收益：按注入占比、查回来源与恢复成功调整层级和粒度。
3. 稳定表示：配置/任务/来源未变时保持序列化字节；用实际 usage 看前缀收益。
4. 反复换入换出：根据移动频率、恢复延迟调整最短驻留与冷却；固定历史仍可读。
5. 后台调度：比较前台 p95 延迟与后台完成时间，校准轮转和批次。
6. 更高层摘要：只有一级摘要规模构成真实负担时再试验聚合，单独测多代误差。

增加关联检索、语义排序或更高层摘要均是独立优化，不自动引入图数据库、RL 或服务端 KV 管理。

## 5. 迁移与完成定义

每次 schema 变化有独立版本与旧数据兼容策略。先读取旧字段并投影到新结构，再逐步切写；不要双写两个独立目录。哈希/来源无法补全时标 unknown 并保留原证据，不编造历史。

功能开关按精细能力区分：统一调度、失效、目录投影、摘要、宿主压缩。关闭恢复能力时撤回依赖它的引用表示，不能留下悬空入口。

C0–C1 完成结构兼容，C2–C5 建立混合表示的程序基础，C6 完成模型协同，C7 依据数据优化。仅完成 C1 不可报告“方案三已落地”。

运行时重大功能完成后按 AGENTS 升级次版本，统一 lockfile/pyproject/README/CHANGELOG、正式副本及发布验证；发布时遵从用户当时安排。当前为未发布的分块重构，发行版本暂留 0.17.0，不发布、不安装正式插件。
