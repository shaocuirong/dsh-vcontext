# 生命周期与资源所有权

## 实例所有权

正式装配由 mount 创建一个共享 Access。
Bridge 与 LiveContext 若收到注入实例，只关闭自己的请求，不关闭共享实例；
独立创建时由各自 dispose 关闭自有 Access。

清理按依赖顺序：取消使用方 → 等待其外层任务结束 → 关闭 Access → 关闭 transport。
LiveContext.dispose 同步禁止回写、取消读取、移除主请求监听并清空缓存，然后返回排空 Promise。
生产、测试和示例的清理调用必须等待这个 Promise。

## 取消与迟到结果

lifecycle 模块把运行时取消、消费者取消和能力生命周期取消合并。
外层等待及时失败，底层 Promise 的最终成功与拒绝仍有处理器。

observation 模块是 lease 的唯一释放者：
- 回调成功、失败均经过 finally；
- 回调进行中取消时回收当前 lease，并使门面失效；
- 宿主忽略取消时，迟到观察只被释放，不进入消费回调；
- 释放器用弱集合保证同一观察只释放一次；
- 释放失败只记录稳定诊断，不覆盖原业务结果。

回调应使用组合 signal 并在异步边界检查取消，不能自行创建无取消的永久后台任务。

## 冷读取串行准入

同一个 Access 只有一个冷读取准入器，总容量为32项，含正在执行的一项。
排队取消会立即归还等待名额。
运行中的宿主若忽略取消，外层可先退出，但准入槽保持到宿主观察真正结束，
之后才能启动下一份冷读取，避免物化两份历史。

LiveContext 对相同会话共享最终派生查询结果；
Access 不向多个使用方共享可变 lease，也不增加长期正文缓存。
队首和观察返回后重新检查活跃会话，支持冷历史读取期间被宿主激活的情况。

## 公共服务与 Cordis

服务能力每次从当前上下文读取，调用方法必须绑定原接收者。
Cordis 每次 get 可能返回新的跟踪代理，不能直接用代理引用判定服务被替换。
身份比较使用 Cordis 公开导出的 original 符号，正常调用仍使用跟踪代理。

通过公开 ctx.inject 生命周期监听 sessions 和 sessionQuery 的撤销；
异步边界额外核对当前服务身份，防止 set 替换后仍消费旧观察。
不拦截 internal/get，不访问 Cordis 私有 registry 实现。
