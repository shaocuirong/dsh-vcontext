# v0.4.0 替换修复节点

## 问题与根因

用户在已有长对话中点击替换，实际上下文没有减少。旧 `/vctx/replace` 只运行插件 working 页归档；该会话没有保存过插件工作页，返回零页并累计执行次数。界面没有足够说明，让零变化看起来像成功替换了聊天历史。

Harness 0.2.1-rc.2 的压缩服务位于 Agent 预设隔离 realm 内，根 Context 和 Agent Context 的普通 get 都可能读不到。需通过公开 `agentPresets.serviceFor(agent, 'compaction')` 获取；历史 Agent 的恢复交由公开 `sessionController.resolveAgent`，避免自行持有 writer 或重建预设。

## 实际行为

“立即替换会话上下文”调用官方 `/compact` 同一接口，由宿主决定安全范围、生成摘要、检查工具配对和并发条件，追加 surface replacement 事件并 flush。原日志保留，实际模型可见历史减少。摘要可能产生模型调用；任务记录在内存中有界保存，重启后需查看实际上下文确认结果。

“仅归档插件工作页”和四种自动策略继续只管理 vctx 页，不自动发起会话摘要调用。没有可归档页时明确显示原因。旧版累计次数不追溯改写。

## 验证与升级

58 项 Node/SDK、65 项 Python 测试通过；Harness 0.2.1-rc.2 隔离实例与真实 Web 按钮验收通过。授权历史副本 1154 条消息变为 3 条，2,680,499 字节变为 237,564，原有 3388 条事件前缀完整保留，源文件 SHA256 不变。仅使用离线摘要钩子测试替换机制，未验证模型摘要质量或供应商缓存收益。详见 [验证记录](../releases/VALIDATION.md)。

拉取更新后完全退出并重开 Harness（包括托盘）。正式链接和审阅 worktree 同步至本次版本；不覆盖数据库或本地 profile。服务缺失、生成中、摘要失败、提交或保存失败均有分类提示；提交/保存状态不确定时先检查实际上下文，不自动重试。
