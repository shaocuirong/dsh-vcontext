# v0.16 长任务与大工具结果

目标是减少开放轮次后续请求反复携带的旧读取正文，同时保留完整证据、工具配对与任务约束。旧历史分页仍只在空闲维护时操作；新路径在公开 `agent/pre-step` 已准入边界执行，不在运行中的工具内重入维护锁。

## 选择与保护

`l1_open_results_enabled` 缺失时默认为 true，受 `l1_enabled` 总开关约束。使用公开 dsh-context 压力与观察版本、模型窗口、输出预留和 L1 工作预算；85%/70% 默认水位及持久 L1 滞回复用现有配置。缺少新鲜压力时跳过。

只处理当前开放 turn 内已结束 step 的成功、纯文本、白名单读取工具结果。保留调用及结果消息身份，只替换结果正文；最近 6 页、最近 8192 估算 tokens、2 步驻留、冷恢复、未完成任务明确来源、未配对工具组与未知替换保护。普通已知 runtime-context 注入原样保留，不将相邻完整工具组误判为未知替换。开放 turn 内任意消息组换出不在本版范围。

每次步骤边界至多计划 2 个不同页面的结果，来源序列化总量至多 8 MiB；候选按结果大小降序、来源序号稳定排序。预览扫描最多 256 页，截断明确显示。正文上限是序列化工具事件数据的 8 MiB，并非裸文本大小。错误、执行、测试、多模态、过小及超限结果保留。

人工计划优先，自动策略不覆盖任何已有人工计划；已明确恢复或已有来源登记的结果不会再次自动外置。手动选择及真正替换前均重新检查任务来源。自动替换前还重新检查当前压力、驻留保护、两个开关和 Surface 版本；切面变化拒绝执行。

## 分块存储

原始宿主日志保持权威。独立 `vcr_transfer_schema1` 增量建立 `vcr_uploads`、`vcr_upload_chunks`、`vcr_plan_policy`，不改主 schema9/vcr1。较小结果沿用 result_store；大结果通过 begin/chunk/finish 保存，单块不超过 65536 Unicode 码点和 262144 UTF-8 字节。每会话最多 4 个未完成上传、每上传最多 512 块；新 begin 清理本 scope 超过 24 小时的未完成暂存，已提交证据不受影响。

逐块验证序号、字节和 SHA256，finish 再验证整体哈希、大小、JSON 和工具身份，然后在短事务中提交原始不可变对象及幂等回执。重开可续传，重复块必须完全一致，完成确认丢失可重放原回执。全局 RPC 上限不扩大。宿主本来已持有完整结果；finish 在 8 MiB 上限内组装和解析，这不是整个 SDK 的常量内存或流式执行保证。

读取先以有界 SQLite 片段校验完整对象，再按 Unicode 码点分页；结果 JSON 响应不超过 128 KiB，并返回内容哈希与续读游标。result_get 保留旧小结果契约，大于 1 MiB 必须用 result_read。显式冷读取只增加普通工具历史及已观察访问计数，不永久加入 L2。

## 提交、失败与观察

先完整保存证据，再持久化计划，后在真实步骤边界追加原生 Surface replacement。宿主 flush 确认后记录投影及计划成功；保存不确定时沿来源链识别已有 replacement 并对账，禁止盲目重复追加。失败计划停止，界面显示状态，需刷新核查并显式重排；暂存上传可在后续步骤续传。卸载取消并等待在途任务。

自动回执保存实际派生字节前后量；已发生替换的重试不伪造原始前量。与宿主结果记录按引用和已确认 surface_seq 去重。最近主会话请求仅接受公开 `isAgentLoopRequest` 标识；辅助调用只保存有界计数和元数据，不覆盖主会话请求。只读自动预览不创建或修改驻留观察。

配置/上传/计划接口仅宿主可用；模型不能开启策略、上传证据或解除保护，只能 result_list/result_read。旧引用继续可读，新大结果需新版有界接口。退出全部共享数据库宿主后升级，勿混跑内核，不覆盖机器配置或用户数据库。

复现实验：`npm run bench:long-task`，使用真实 Cordis、dsh-context、AgentLoop、ToolRuntime、SessionProjection 和离线适配器，无供应商调用。具体字节、成本和桌面验收边界见[验证记录](../releases/VALIDATION.md)。
