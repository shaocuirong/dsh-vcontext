# v0.17 证据目录与三级来源摘要

本版解决全文换出后只剩短引用、难以判断内容的问题。它提供可读导航与可追溯摘要，不扩大自动换出范围，不让摘要成为事实验证或任务完成依据。设计受 [billion-context](https://github.com/ranxianglei/billion-context/tree/c499b14508e6a4296df7db48ecf29eb40532c4c8) 启发，独立实现，没有引入其代码、内核、代理或许可证依赖。

## 来源与摘要

- 历史索引从本会话拥有的原生归档marker派生。最多3条原文摘录、6个显式文件路径及6个工具名；正文只检查有界前缀，不称为语义摘要，不据此断言测试通过。历史版本是归档marker及其原始来源身份的SHA256，不是正文哈希；正文读取继续使用原有content_hash契约。Fork继承的父marker不能作为本会话证据。
- 已保存工具结果使用不可变result引用与原有content_hash作为版本。目录不经RPC取回全部结果；显式读时才完整校验并有界读取。
- 模型通过正常vctx工具调用evidence_note，必须提交request_id、标题、摘要和1–8个 `{ref,source_version}`。宿主逐项验证来源存在、会话归属与版本，底层ved_*不开放给模型。人工界面固定origin=human，模型入口固定origin=model，调用方不能伪造人工或已验证身份。
- 原始来源为第0级；笔记级别为1+来源的最高级别，最多3级。来源笔记必须先存在，因而图无环。每条摘要最多1600 Unicode码点，标题120；内容、来源、作者类型与级别一起哈希，不可修改或删除。不同判断独立保留，摘要始终not_tested。

## 保存与读取

独立ved_schema1/ved_notes增量表，不改主schema9及宿主日志。每会话request_id唯一，同输入重放原回执，不同输入拒绝；事务失败回滚。先冻结调用数据再异步验证，每会话最多1个保存、全局最多32个。卸载停止新调用并等待在途保存；不确定结果使用同一request_id与内容核对，界面不盲目重试写入。

evidence_list在最新256个归档、100个结果、100条笔记中搜索标题、摘录、路径和摘要全文；这是有界导航扫描，未建立永久全文索引。返回分页最多32项，响应受128KiB包装预留约束，截断明确显示。笔记列表仅预览前200码点，显式read才返回完整摘要与来源。原文默认读取4096码点，继续受旧接口128KiB上限保护，不会自动永久准入L2。笔记读取按summary/cold记录可观察访问，版本检查不计为实际读取。

## 模型请求与界面

vctx_evidence在原有动态上下文之后注入，最多8项/4096 UTF-8字节，标记untrusted_navigation。当前扫描中已被上层笔记引用的条目不重复注入；所有下层笔记与原文仍可显式检索。上层摘要不会自动替换或清理宿主原消息、旧运行时快照或数据库证据。版本/标题/摘录不随刷新时间变化，未变目录保持相同字节；这不等于供应商缓存命中保证。

新持久设置evidence_directory_enabled缺失时初始化true，可独立关闭目录注入；关闭后查询与原文恢复仍可用，L1/L2及已保存笔记不受影响。模型不能改此开关。目录失败注入available:false，不沿用上次成功内容冒充当前状态。

看板提供独立证据目录标签、检索、原文索引/人工笔记/模型摘要标签、来源链、分页读取和人工归纳。保存超时保留同一身份与输入，取消编辑才产生新尝试；所有内容以普通文本显示。

## 试验边界

本版不启动后台摘要模型。主模型可以在正常任务内保存摘要，这仍可能增加普通工具调用/后续步骤成本；不会自动为全部旧历史生成语义摘要。摘要可能遗漏或有误，应回查精确错误、数值、决定理由和矛盾来源。三级目录归纳是导航视图收敛，未实现按摘要质量自动选择/晋升/回滚的完整压缩控制器。真实模型长期自主采用、任务正确率及供应商缓存/费用A/B仍待验证，不能推广离线fixture为真实质量收益。

复现：`npm run bench:evidence`。使用官方AgentLoop、真实vctx工具、原生Surface及临时SQLite；下一请求确实看到工具写入的摘要，被换出的全文缺席，引用可读取且V4完整回放一致。实际结果见[验证记录](../releases/VALIDATION.md)。
