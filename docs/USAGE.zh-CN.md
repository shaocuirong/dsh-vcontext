# 上下文缓存使用说明

## 开始使用

1. 完全退出 DeepSeek Harness（包括托盘），再打开。插件安装在桌面端 `desktop` 配置中。
2. 在输入框旁点击“上下文缓存”，按钮会显示“开”或“关”。未生成会话时可预选，下一次进入的首个未配置会话会接收该选择；已有独立设置的会话不会被覆盖。
3. 在会话导航中点击“上下文缓存”，或打开右侧同名面板。
4. 也可输入 `/virtual-context on`、`/virtual-context off` 或 `/virtual-context status`。

按钮的开关控制面板显示。插件不会自动复制整段聊天记录，也不会删除宿主消息。需要保存的内容由 Agent 调用 `vctx` 写入。

如果切换失败，会显示错误；连接超过 8 秒会提示超时，可再次点击重试。

## 设置页

打开“设置 → 上下文缓存”。显示偏好立即保存到当前浏览器；归档策略需要点击“保存归档策略”，保存在本地数据库，桌面端和同一配置的其他界面共享。

| 设置 | 含义 |
| --- | --- |
| 显示位置 | 面板总开关、会话标签页、右侧侧栏 |
| 看板内容 | 紧凑模式、换入换出记录、供应商缓存命中记账 |
| 查询事件条数 | 20–2000 条；滑块和数值框同步；记录表展示最近 12 条、曲线展示最近 60 次 |
| 自动刷新 | 默认每 2 秒；可选手动或每 2/5/10/30/60 秒；旧设置中的自定义频率也保留，最低 1 秒 |
| 轻量查看 | 100 条，手动刷新，紧凑显示 |
| 日常使用 | 200 条，每 5 秒刷新 |
| 详细排查 | 1000 条，每 2 秒刷新 |

“恢复默认”只重置显示偏好，不重置归档策略或删除页面数据。

## 工具结果外置与恢复（0.6.0）

在看板中点击“刷新可外置结果”，选择一条结果的“排队外置此结果”。只列出当前会话可见、可配对、成功的较大文本读取结果（2 KiB–1 MiB，另受传输编码上限约束）；错误、执行/测试、多模态、vctx 自身和 Fork 继承结果保持原样。不自动移出所有旧结果，也不读取当前磁盘文件替代历史原文。

插件先存完整工具结果和计划，明确显示“等待下一次模型步骤”。在下一次真实对话轮次的请求前，Harness 才将原位置换为固定 `vctx://result/...` 引用；保存计划不等于已外置，也不会为了应用计划自动发送消息。无需模型摘要，原日志保留。“排队恢复原文”同样在下一次模型步骤前将引用原位换回，不增加重复工具回复；尚未应用的外置可取消。

用 `vctx result_list {}`、`vctx result_read {"ref":"vctx://result/...","offset":0,"limit":65536}` 可分页读取；返回的是原工具结果数据的 JSON 文本，读取会增加普通工具历史，与原位恢复不同。

会话生成中、候选被其他投影覆盖或宿主持久化失败时会显示冲突或计划未完成；提交不确定时先刷新确认状态，不自动重试变更。队列持久化，重启后仍等待真实步骤；HTTP任务状态只在当前宿主进程保留，不能代替实际Surface。结果变更入口仅供本机同源浏览器使用，非远程鉴权API。显示的字节量不是精确 Token 数。0.6.0历史迁移保持主schema7/vc2、首次增加vcr1前生成pre-result1备份；当前0.7.0升级按后文schema8规则，不覆盖数据库或profile。详见 [投影契约与论文依据](PROJECTION-0.6.0.md)。

## 归档会话历史（0.9.0 / 0.10.0）

看板“归档旧聊天与工具结果”会把完整旧轮次的模型可见消息替换为一条短引用。原始宿主事件日志不删除，最近两轮和宿主系统/开发者消息保留；下一次模型请求不再携带被归档的旧聊天与工具结果原文。它离线运行，不调用摘要模型，与下方“仅归档插件工作页”和“立即压缩会话上下文”不同。

归档成功后显示消息数与实际上下文字节的前后值，以及 `vctx://history/...` 引用。在同一会话使用 `vctx history_read {"ref":"vctx://history/...","offset":0,"limit":65536}` 分段取回原始消息。读取会产生新的工具历史，不会将整段对话按原角色原位恢复。没有完整旧轮次、维护锁被占用或保存状态不确定时按提示刷新再核对；不要盲目重复点击。一次最多256条消息及8MiB正文；详情和论文依据见 [归档契约](HISTORY-ARCHIVE-0.9.0.md)。

0.10.0 增加归档清单、检索和按消息读取：`vctx history_list {"limit":20}` 列出本会话的归档引用与大小（最多100条，不含正文）；`vctx history_search {"query":"关键词","limit":5}` 只扫描最近8个归档、最多2048个源事件 / 4MiB文本，返回不超过160字符的摘录；`vctx history_read {"ref":"...","seq":<原始事件序号>}` 只读回该归档中的一条原始消息。归档本身可带 `request_id` 与 `expected_surface_seq`：同一 request_id 与相同保留轮数重试返回原回执，不会再次追加；预览后会话已变化会拒绝提交。看板卡片也显示归档清单和搜索结果；点击归档时自动生成 `request_id` 并携带预览的 `expected_surface_seq`，预览未变时重试复用同一身份，成功后或预览刷新后换新。提交结果不确定时先刷新再重试，不要换新 ID。若服务端返回 CHANGED（预览已过期），卡片会自动重新读取预览并清空本次身份，下一次点击为新 Surface 生成新的 `request_id`；重放成功时标注“重放原回执，未追加新记录”，显示原归档时的前后消息数与字节。归档清单、检索和重放只认本会话引用，Fork 子会话不继承父会话的归档。检索是大小写不敏感的离线词法匹配，不是语义搜索；最近 8 个归档的上限有单元测试覆盖，2048事件 / 4MiB扫描上限为代码检查、未做大规模压力测试。详见 [0.10.0 设计](HISTORY-VCONTEXT-0.10.0.md)。

## 压缩会话上下文

看板中的“立即压缩会话上下文”（旧名“立即替换会话上下文”）调用 Harness 官方压缩服务，将旧聊天历史替换为摘要，并保留原始会话日志。它使用宿主配置的摘要模型，可能产生一次模型调用；与工具结果外置的离线运行不同。该功能已在 Harness 0.2.1-rc.2 验证，缺少接口时会明确提示。

点击后按钮显示运行中，完成后显示替换条数、前后消息数与字节数；切换页面再回来仍可读取本次结果。尚未激活的历史会话由宿主恢复，生成中的会话需等待当前操作结束。没有可压缩历史、摘要失败、并发冲突与保存失败各有提示；提交或保存结果不确定时先检查上下文和宿主日志，不要连续重试。任务记录仅在当前宿主进程中保留，重启后需查看实际上下文确认结果。

## 插件工作页归档策略

这里的“归档”是将驻留的 `working` 工作页换出到 `archive` 归档，从后续插件快照移除。正文、修订和检索能力保留。需要时使用 `recall` / `page_in` 换回。

| 模式 | 触发条件 |
| --- | --- |
| 手动归档（默认） | 在看板点击“仅归档插件工作页”；不自动换出 |
| 每 N 轮归档 | 收到 N 条新的用户消息后触发；同一轮的工具调用和多个模型步骤不重复计数；运行环境、工具通知及其他内部注入不计入用户轮次 |
| 达到阈值归档 | 模型步骤开始前，检查插件驻留快照占用是否达到预算的指定百分比 |
| 轮次或阈值触发 | 两者任一满足即执行 |

替换间隔范围 1–100 轮；触发阈值 10%–100%；目标占用 5%–95%，且必须低于触发阈值。每次执行后轮次计数归零。计数和最近执行结果持久保存，重启不会重置。

可选换出优先级：价值密度较低的工作页优先，或最久未使用的工作页优先。可保护最近 0–20 页工作页，默认保护 1 页；所有核心页与大纲核心索引始终保留。

例如：选择“轮次或阈值触发”，间隔 5 轮、阈值 80%、目标 50%、保留最近 1 页。达到条件时逐页归档可换出的工作页，直至低于 50% 或没有可换出的页面。如果核心页和受保护工作页本身超过目标，看板会明确显示“未达到目标”，不会删除或强制归档这些页面。

策略对同一个 namespace 的会话统一生效。切换自动模式后，在模型步骤或新的用户消息到来时检查；没有后台定时清理任务。面板关闭时策略依然有效。默认字节预算不等于模型完整上下文窗口；要换出旧聊天和工具结果，使用上方“归档旧聊天与工具结果”，需要摘要则用“立即压缩会话上下文”。工作页归档不会调用摘要模型；没有工作页、所有页受保护或低于目标时，明确说明未归档且不增加执行次数。已有旧版累计计数保留。

## 当前上下文与最近请求

看板上方的“当前实际上下文”每次查询都会调用宿主 `Session.deriveMessages()`，包含当前系统提示、用户/助手消息和工具结果，遵循宿主的消息压缩与替换。它不会只读取启动时的 `request/header` 或 `request/context`。未激活的历史会话通过宿主只读观测日志还原，无需新发消息；缺少历史接口或读取失败时会明确提示。

“最近请求”来自插件加载后捕获的 `llm/stream` 调用，按会话隔离，显示发送时间、消息数量和内容预览。当前消息可能已经包含最近调用后新生成的回复，因此两者不同是正常现象。最近请求只保留在内存，重启后需等待下一次调用，最多保留 128 个会话；这是送入 LLM 接口的消息，不是供应商适配器转换后的最终网络报文。

预览保留完整内容的开头与结尾各 32768 字符，超长中段省略，保留最新消息可见。统计和指纹覆盖全部已过滤的消息与工具定义 JSON；不含 API Key、连接头和适配器私有回放数据。字节数不是 token 数。生成中的流式回复尚未提交到会话时，不计入当前派生消息。

默认每 2 秒刷新；旧版未设置自动刷新的偏好会迁移到 2 秒。之后可在设置中明确选“关闭”，保留手动刷新。下方“插件缓存页”是独立页存储的预算和统计，不代表模型完整上下文容量。

主导航的上下文缓存看板隐藏聊天输入框，切回聊天立即恢复。只打开右侧上下文缓存面板时仍可正常输入。

## 看板卡片

- **dsh-context 联动**（0.3.0）：安装并启用同 profile 的 dsh-context 后显示组成、压缩统计和累计用量。宿主 token-meter 优先，没有该投影时明确显示启发式估算；未连接不影响页面缓存。
- **运行诊断**（0.3.0）：调用、失败、取消、慢调用与最近告警。详细状态可读取 `/vctx/health?session=<会话id>`；错误分类和配置见 [API](API.md#健康与联动030)。
- **窗口构成**：核心前缀、大纲、工作尾部和剩余驻留预算。
- **工具结果外置与恢复**：逐条选择工具结果，保存原文、驻留引用、原位恢复。
- **归档会话历史**：完整旧轮次的聊天和工具结果换成引用，展示实际上下文前后字节。
- **压缩会话上下文**：官方摘要压缩任务状态、历史条数和前后上下文大小。
- **插件工作页归档**：当前模式、本周期轮数、累计实际执行次数、最近归档数量或未归档原因、独立归档按钮。
- **重写曲线**：每次快照变化的失效字节；绿色表示稳定前缀仍可复用。
- **缓存命中记账**：仅展示模型供应商实际返回的用量；没有真实调用时显示空状态。
- **换入换出记录**：页面名称、原因、层变化、字节数。自动策略记录为 `policy_replace`，原因是 `turns`、`threshold` 或 `manual`。

布局会随标签页和窄侧栏宽度自动调整；也可以使用“刷新看板”手动更新。

## 让 Agent 保存和找回内容

### 结构化操作与版本资源（0.5.0）

活跃会话的 Bridge 自动索引宿主操作元数据，包含 Native 和 PTC 子调用；不复制原始参数或工具结果。看板“版本化状态与会话索引”显示游标、操作、资源版本与摘要数量。旧的冷会话阅读仍是只读，不会自动激活所有历史 Agent。

可让 Agent 调用 `vctx`：

1. `operation_list` 查询操作 ID 和来源序号。成功工具仍是 `succeeded / not_tested`。
2. `resource_store` 使用 `request_id`、相对 `path`、`content` 保存明确文本，记录返回的 `resource.ref`。
3. 更新同一路径时传 `expected_ref`，避免覆盖并发变化；再次发送同一逻辑写入时复用原 request_id 和参数。
4. `resource_read {"ref":"vctx://resource/..."}` 精确读取历史版本；按 path 读取则只用当前会话指针，不自动跟随别的会话最新文件。
5. `summary_store` 提交摘要与 `sources:[ref...]`；摘要不覆盖原文、不会自动成为已验证事实。

这些操作不自动把全文驻留在插件快照中；显式 read 返回的文本会进入正常宿主工具历史。按需恢复和实际压缩是不同动作。

### 可选文件捕获

文件捕获默认关闭。需要这个读取能力时，在本机 profile 的现有 `dsh-virtual-context` 行内保留其他配置、仅加入：

```yaml
- id: dsh-virtual-context
  config:
    # 保留这里原有的 namespace、预算和其他设置
    resourceCapture: true
```

退出并重新启动 Harness 后，调用 `resource_capture {"path":"vcontext/core.py","request_id":"capture-1"}`。它仅通过宿主文件服务捕获当前项目内单个完整 UTF-8 文件（最多 256 KiB），返回 ref/hash；支持 BOM、CRLF 和 Unicode，不扫描仓库。后端拒绝、越界、二进制、过大或读期间变化会失败。请按实际路径调整示例，不替换整份 profile。

文件捕获可传 operation_id 关联操作，但只证明“捕获时看到此内容”，不能证明该操作是唯一修改者；不会补造修改前原文，也不创建 Git commit。`resource_store` 保存调用者文本，不能伪造宿主来源 source_revision。完整参数见 [API](API.md#结构化状态与资源050)。

### 数据库升级

0.8.0升级前先完全退出所有使用同一数据库的旧宿主，包括系统托盘。首次打开旧schema1–8磁盘库时先用SQLite backup创建同目录唯一 `.pre-schema9-<id>.bak`，再事务迁移到schema9/vc2/vcr1/vcs1/vct1；失败回滚，不覆盖数据或配置。旧0.7拒绝schema9，但不能阻止升级前已打开的连接继续写，禁止混跑。降级需单独保留升级后数据，再人工选择旧备份；插件不自动覆盖恢复。

### 会话资源快照（0.7.0）

1. 在“会话资源快照”卡片点“刷新快照”，绑定并同步当前会话；先用 resource_store 或显式启用的 resource_capture 收录需要管理的文件。
2. “保存当前清单”冻结全部已收录资源，说明仅用于识别。它不扫描其他文件，也不自动加载全文。
3. 选择列表项或粘贴同项目明确的快照引用，点“固定此快照”。此后 vctx 按 path 只读该清单，缺失路径报错，资源写入/捕获拒绝。其他会话更新不会改变它。
4. “返回保留工作集”找回固定前的可写集合；“从此快照建立独立工作集”则复制所选集合，先自动保存被替换集合的安全快照。两种动作都不修改磁盘。
5. 可查看版本清单、选择另一个快照为比较基线；面板每页最多50项，其余使用 snapshot_read/diff 的 offset/limit 分页。

所有变更带 revision 和 request_id，冲突或提交不确定时按钮暂停，先“刷新快照”核对，不能连续盲点。自动化重试同一逻辑请求要保留原 request_id 与输入；迟到重放不会倒回新的目标。

也可让 Agent 先执行 snapshot_status，再用返回的 target.revision 调用 snapshot_create/checkout/detach/branch。固定信息会以简短元数据进入下一次实际模型请求，原文仍按需 resource_read。原生文件 read/write 仍访问真实工作区，既有聊天/工具结果不会自动撤回；DSH Fork 切点没有自动资源继承，须明确选择匹配的快照。需要历史磁盘环境时另用 Git/worktree。完整范围、论文依据与恢复策略见 [快照设计](SNAPSHOTS-0.7.0.md)。

### 任务与执行状态（0.8.0）

在卡片点击“刷新任务”，再展开“新建任务 / 子任务”。填写目标与验收条件；父引用留空建立根任务，填写已有父引用建立子任务。选择列表条目查看详情，点“设为当前任务”后，后续真实工具调用将按当时焦点关联，迟到结果仍属于原任务。

保存进度与下一步时使用任务版本和会话修订CAS。完成只标记“报告完成”，不变成测试通过；未结束的子任务会阻止父任务完成。失败和放弃路径保留在列表，当前路径会清除，可建立新的尝试。任务分支保留来源，目标可继承，但进度、审核和子树不复制，资源快照不切换。

关联历史证据时，操作ID来自 operation_list，资源ref来自不可变版本。人工审核前先在宿主轨迹核对原文，勾选已关联、已结束的实际操作，填写说明，再记录通过或失败；不能以vctx管理调用自证成功。审核是人工判断，原工具记录仍为not_tested。预览后任务、资源或实际执行变化会拒绝提交，已记录审核也会过期；刷新后重新核查。刷新会保留尚未提交的表单文本，可展开“核对已保存进度”比较服务器当前版本。

任务状态独立于聊天保留。宿主请求前注入最多8KiB当前路径、进度、下一步和审核状态；不自动读取全部资源或旧任务轨迹。旧runtime快照可能仍留在历史，请以本次请求最后一份任务JSON为当前状态。历史表与版本用于查证，不自动把失败路径变成当前事实。详见 [任务执行设计与论文](TASKS-0.8.0.md)。

### 原有页面工具

示例请求：

> 调用 vctx，operation=write，input={"title":"项目约束","content":"离线优先；数据库使用 SQLite。","tier":"core"}。

> 将阶段性结果以 working 页保存，并在切换任务时用 recall 检索相关内容。

实际工具参数的 `input` 是 JSON 字符串，例如：

```json
{"operation":"recall","input":"{\"query\":\"项目约束\",\"limit\":3}"}
```

默认数据库位于 `~/.dsh/dsh-vcontext/context.db`，设置了 `DSH_HOME` 时相对于该目录。插件默认优先寻找 Harness 已下载的 Python 运行时，然后使用系统 Python；也可设置 `VCTX_PYTHON` 或在本地 profile patch 中显式指定绝对路径。预算、数据库和解释器等宿主参数可在 `~/.dsh/profiles/desktop/cordis.patch.yml` 中覆盖，修改后重启。链接安装的仓库目录不能随意移动。
