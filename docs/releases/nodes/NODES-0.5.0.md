## 审查后修正

1. 使用当前 Agent 的 fs 服务处理捕获，不直接读取宿主 Node 文件系统；默认 `resourceCapture=false`，显式启用才增加文件读取能力。
2. 模型 `resource_store` 不能提供宿主来源 source_revision；手工文本、捕获时点和功能验证分开。
3. 官方 PTC 内层调用保留真实 ID 与事件类型；与 Native 不透明 ID 分域，不依赖字符串前缀碰巧唯一。
4. 合法工具结果裁剪作为 projection 证据，不归为第二次执行；继承前缀不重复计算为子会话操作。
5. 不对长历史逐条重复解析；只校验元数据边界及新增后缀，明确宿主不可变历史的信任边界。

## 验收

83 项 Node/SDK、102 项 Python 测试通过。独立 Harness 0.2.1-rc.2 的真实文件工具→操作索引→两个资源版本→旧原文恢复→摘要来源→原生看板链路通过。详情见 [验证记录](../VALIDATION.md)。没有真实摘要模型或论文基准跑分，不把字节、存储规模和供应商 Token 混为一谈。

升级保持本地 profile、旧页面和用量；首次打开旧库自动生成唯一 SQLite backup 后迁移。默认不启用文件捕获；回退旧插件需退出所有使用该库的宿主并人工选择备份，禁止自动覆盖数据库。
