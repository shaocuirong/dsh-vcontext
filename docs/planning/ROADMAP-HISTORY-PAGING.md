## 目标

按四个阶段推进：

1. 读取边界修复（v0.10.3）
2. 细粒度分页（v0.11.0）
3. 可配置虚拟配额（v0.12.0）
4. 自动调度（v0.13.0）
5. v0.14.0 为条件性扩展：大结果与开放 turn 内的更细换出

先让页面划分、状态记录、读取边界可靠，再让控制器自动决定换出哪些内容。不要同时堆入自动策略、Git DAG、MCP 统一接口或强化学习。

## L1 / L2 / L3

| 层 | 定义 | 权威 |
|---|---|---|
| L1 模型可见上下文 | 宿主实际派生的请求内容与已确认 Surface | DSH Session Surface / 真实请求 |
| L2 在线虚拟集合 | 允许自动检索、选取和加载的资源集合，具有可配置容量 | 插件 SQLite 在线成员身份 |
| L3 冷历史 | 不参与默认自动检索，但仍可按明确引用恢复 | 宿主日志 + 页面/资源引用 |

L1 可见状态与 L2 在线身份必须分别记录。页面移出 L2 不等于自动从模型请求消失；读取 L3 也不等于自动把整页加入 L2。

## v0.10.2 当前缺口

| 当前实现 | 影响 |
|---|---|
| selectArchiveSpan() 按完整旧 turn 选取，默认保留最近两轮 | 需要新的分页规划器；旧归档接口继续兼容 |
| history_read(..., seq) 直接返回完整消息 | 单条读取没有输出上限，3 MiB 结果会整条进入工具历史 |
| 工具结果投影只接受指定读取工具的成功纯文本结果，2 KiB–1 MiB | 3 MiB 结果需要独立扩展存取链路，不能认为现有路径已支持 |
| core.py 默认以 UTF-8 字节数作为预算 | 新增 Token 配额时必须明确单位，不能直接把旧 budget 改名 |
| usage_events 只有 scope/turn/step/tokens/source | 按 Provider/Model 分组需要加列或从 request header 关联 |
| 宿主日志、Surface、SQLite 职责不同 | 跨系统提交必须幂等 + 对账，不能只靠 SQLite 事务 |
| 历史页面状态主要从 marker 解析 | 没有 vh_* 页面注册表、驻留观察和访问账本 |
| history_search 只扫最近 8 个归档 / 2048 事件 / 4 MiB | 需要跨全部历史页面的可重建索引 |

已确认的 DSH Surface 规则：

- 换出范围必须在当前 Surface 中位置连续；sourceEventSeqs 按 Surface 顺序，不要求数值连续。
- 宿主用 surface.nodes.indexOf(startSeq/endSeq) 定位，只要求 Surface 索引 startIdx <= endIdx；数值上 startSeq 可以大于 endSeq。
- sourceEventSeqs 必须包含这段 Surface 切片的每一个被遮蔽节点。
- 提交前必须重新验证 Surface；不能直接使用持久化的旧边界。
- toolPairingBalancedBefore/After、tool-result-pruner、dsh-compaction-basic 在安装版 app.asar 中确认存在，但不在当前插件依赖里，属于 host-only；先验证公开导出/权限，再决定是否使用。

## 阶段 1：v0.10.3 有界历史读取

改动集中在 history_read：

1. 单条消息读取也支持分段；大文本返回片段、续读游标、版本与截断标记。不要把截断正文伪装成完整消息。
2. 限制最终响应大小；覆盖正文、JSON 包装、引用、摘要、元数据；字符上限与 UTF-8 字节上限分别检查。
3. 游标绑定资源版本或内容哈希；不匹配返回错误，避免续读错位。明确 offset 按 Unicode 码点还是字节计算。
4. 兼容旧 vctx://history 引用；小消息尽量保持原响应形式，大消息分段行为同步更新工具说明与调用端。
5. 记录读取峰值内存；返回有界不等于处理有界。

测试：中文/emoji/换行/转义混合；单条 3 MiB；多次续读无遗漏无重复；旧归档/Fork 归属；大量元数据或工具参数；响应总量有界。

## 阶段 2：v0.11.0 细粒度分页与手动换出

目标：在一个已完成的旧 turn 中，只换出选定的合法消息组，并能说明换出了什么、来源是什么、操作是否已持久化。

四个组件：

| 模块 | 职责 |
|---|---|
| adapter/history-segmenter.mjs | 从当前 Surface 生成合法原子组与页面 |
| adapter/history-planner.mjs | 根据保护条件、预算和页面价值生成计划 |
| adapter/history-executor.mjs | 在宿主允许的时机验证、提交、确认替换 |
| vcontext/history_pages.py | 页面身份、来源、操作记录、最后确认状态 |

现有 history-archive.mjs 保留兼容入口，逐步委托新组件。

页面划分：

- 原子组：不能被非法拆开的消息结构，例如 assistant 并行工具调用及对应结果。
- Page：一个或多个连续原子组组成的管理单位。
- 默认不跨 turn，优先贴合 step；step 只是候选边界，tool pairing 合法性才是必要条件。
- 以当前 Surface 顺序判断连续性；不要求原始事件 seq 数值连续。
- replacement 节点沿来源链追溯，不能按追加时间确定历史位置。
- 未识别替换结构先标记不可操作。
- 已封存页面不因重扫重新分配 ID；确需重分组时建立新页面及替代关系。
- 页面大小是目标值，不是强行拆开工具组的硬上限；超大原子组标记 oversized，选择整体处理、正文瘦身或暂缓。

页面状态至少三个维度：

| 维度 | 建议取值 | 含义 |
|---|---|---|
| 生命周期 | open / sealed / obsolete | 页面是否完整、是否仍有效 |
| L1 可见形式 | full / summary / absent / unknown | 当前确认的模型可见状态 |
| L2 在线身份 | online / cold | 是否进入默认检索与准入集合 |

pinned、保护原因、版本有效性另设字段。unknown 很重要：宿主提交结果未确认时不能默认标成已换出。

最小数据库结构：

- vh_pages：页面 ID、归属、逻辑版本、生命周期、估算大小。
- vh_page_sources：原始事件身份、页内顺序、来源哈希。
- vh_surface_observations：最近确认的 Surface 位置、可见形式、观察版本。
- vh_operations：幂等键、计划指纹、提交状态、错误与回执。
- vh_accesses：逻辑需求、读取来源、返回量、恢复耗时。

历史正文继续引用宿主日志。全文索引是派生数据，单独计入物理存储成本。

执行顺序：生成计划 -> 持久化操作意图 -> 获取宿主维护机会 -> 重验边界 -> 追加替换 -> 确认宿主持久化 -> 更新数据库回执。

失败恢复：

- 宿主已保存、SQLite 更新失败：标记待对账，重试复用已有替换。
- 宿主保存结果不确定：先查询/重放确认，不直接再追加。
- 批量途中失败：返回逐页结果，不宣称整批原子成功。
- 同一请求 ID 配不同计划：拒绝复用。
- SQLite 事务不跨越等待宿主的整个过程；短事务保存意图和回执。

v0.11.0 默认只开放已结束历史的手动 Page-Out；开放 turn 内的任意组换出留待后续验证。

## 阶段 3：v0.12.0 可配置虚拟配额

模块：vcontext/quota.py、vcontext/history_search.py、adapter/history-access.mjs、配置/界面。

在线容量：

Q_s = sum over u in U_s of estimated_tokens(u)

U_s 是作用域内在线成员引用的唯一逻辑内容单元集合：

- 同一事件被多个页面引用只计一次。
- 同一资源版本重复引用只计一次。
- 不同版本按不同逻辑身份处理；底层内容相同可物理去重。
- 原文与独立摘要分别计量。
- 页面拆小不能降低总计量。
- 删除搜索缓存只减少存储占用，不自动减少在线逻辑容量。

Token 计量保存 estimator_id 与版本；模型未知时显示估算值，不宣称等于供应商真实 Token。

会话准入同时检查本会话额度、项目额度、已预留未完成容量；项目共享逻辑单元使用引用计数。并发准入在 SQLite 短事务内检查与预留：

Q_committed + Q_reserved + delta_Q <= Q_max

L2 准入/降冷以数据库在线身份提交为准；L1 换出/恢复以宿主确认的 Surface 状态为准。不要为等待 L1 冻结所有 L2 操作，也不要因 L2 降冷提前宣布模型输入减少。

满额/调低上限行为：

- 高水位：尝试整理至低水位。
- 单页大于整个额度：拒绝整页在线准入，允许有界片段读取。
- 所有候选受硬保护：停止整理，报告阻塞原因。
- 用户把上限调到当前占用以下：显示超限，暂停新增准入并尝试整理。
- 保护集合本身大于新上限：保留保护集合，明确显示无法满足配额。
- 冷历史被明确读取：可临时返回片段，不默认永久加入 L2。

配置草案（试验初值，不是现有配置）：

historyPaging:
  enabled: true
  mode: manual
  targetPageTokens: 4096
  maxPagesPerBatch: 8

virtualContext:
  mode: enforce
  sessionMaxOnlineTokens: 1000000
  projectMaxOnlineTokens: 4000000
  highWatermark: 0.85
  lowWatermark: 0.70
  protectRecentPages: 6
  protectRecentTokens: 8192
  minResidentSteps: 2

historyRead:
  maxReturnedTokens: 8192
  maxResponseBytes: 131072

storage:
  maxPluginStorageBytes: 2147483648
  allowAutomaticSourceDeletion: false

校验 0 < lowWatermark < highWatermark < 1，并明确 Token 估算器。maxPluginStorageBytes 只约束插件拥有的存储；宿主日志单独展示，不能假装由插件配额控制。

## 阶段 4：v0.13.0 自动整理

两个控制循环：

| 控制器 | 对象 | 触发 |
|---|---|---|
| L1 控制器 | 实际模型输入 | 接近输入预算且宿主提供合法操作时机 |
| L2 控制器 | 在线虚拟集合 | 达到在线配额高水位或新资源申请准入 |

L2 降冷通常不需要改写 Prompt，可减少前缀缓存失效。实际上下文预算还要覆盖系统提示、工具定义、用户输入、摘要、加载片段，并预留输出空间。

第一版自动策略保持可解释：

1. 排除开放页面、未完成工具组、版本不明、硬保护内容。
2. 优先已完成任务、长期未访问、无活动依赖的页面。
3. 比较释放量、恢复代价、预期 Prompt 改写代价。
4. 达到目标或没有合法候选时停止。
5. 记录每个页面被选中或被保护的原因。

最近页面保护是软保护；显式 pin 和明确必要依赖是硬保护。任务树只提供候选信号，不能直接推断“任务完成所以证据无用”。

防抖：高低水位滞回、最小驻留步数、最近冷恢复保护、每轮整理量上限、频繁迁移退避。

统计拆分：L1 驻留命中率、L2 在线命中率、冷恢复率、供应商缓存命中率、换出收益、恢复成本。需求需要原文时只有摘要驻留不算原文命中；不可观察的模型内部访问不进入分母。

## v0.14.0 条件性扩展

v0.10.2 工具结果上限 1 MiB；3 MiB 或更大结果要检查整条链路：宿主读取 -> 序列化 -> RPC -> 内容存储 -> 哈希校验 -> 正文投影 -> 分段恢复。不能只调大一个常量。

要求：分块写入/受控流式存取，减少多份全文副本；完整保存并校验成功后才提交正文替换；保留原调用 ID、结果角色与关联；失败结果、多模态、非读取工具结果逐类支持；开放 turn 内换出必须通过宿主能力测试；无法安全换出时返回明确原因。

3 MiB 成功处理是该阶段验收项，不是 v0.11.0 已保证的能力。

## 必须遵守的约束

- 不声称跨 DSH、SQLite、Git 的单一事务；用幂等键、短事务、对账。
- 不把 SQLite 状态当作 L1 权威；resident 需要 Surface 确认。
- 不把字节数当 Token；Token 估算带 estimator_id。
- 不依赖 host-only 内部 API，除非公开导出/权限已验证。
- 不自动删除宿主日志；不静默解除保护；不伪造合规。
- v0.11.0 不加入自动策略、Git DAG、全量语义检索、RL、MCP 统一接口。
- 任何版本发布前至少通过现有 Node、Python、发布检查；新增真实 SDK/AgentLoop 验收：换出后下一次真实请求确实不含目标全文。
- 兼容：增量表、独立 schema 版本、功能开关；关闭新功能只停止新操作，旧引用仍可读；旧二进制打开新库需单独测试，不默认承诺降级。
- 未经明确要求，不创建 tag、GitHub Release 或 npm 发布。

## 待定决策

6. 目标 page 大小 32 KiB / 4096 tokens 的初值需用真实长 turn 数据调优。
